# 현재 흐름 조사

기존 동작이 이번 설계에 영향을 주는 경우, 첫 설계 질문 전에 관련 프로젝트와 제공된 자료를 읽는다. 사용자가 언급한 기능과 현재 단계에 필요한 범위부터 찾고, 범위가 불분명하면 확인 가능한 부분을 먼저 조사한다. 조사만으로 판단이 끝나지 않는 선택은 사용자에게 남긴다.

1. 사용자의 행동이나 외부 요청이 시작되는 화면, API, 이벤트 또는 작업을 찾는다. 실제 진입점을 확인하지 못하면 추정하지 않는다.
2. 관련 호출과 데이터의 흐름을 따라 처리 책임과 경계를 확인한다. 필요한 경우 저장소, 외부 서비스, 비동기 작업과 결과를 받는 곳까지 살핀다.
3. 설계를 바꿀 수 있는 성공, 실패, 재시도와 기존 테스트를 확인한다. 코드에 없는 운영 상태나 화면 동작은 확인했다고 말하지 않는다.
4. 확인한 사실마다 파일 경로와 필요한 경우 코드 위치를 남긴다. 확인하지 못한 흐름, 접근할 수 없는 자료와 가정은 구분한다. 요청에 불필요한 경로까지 모두 조사하지 않는다.
5. 사용자에게 중요한 현재 동작과 확인 범위를 짧게 설명한다. 주요 동작마다 실제로 읽은 파일 경로를 함께 보여줘 사용자가 근거를 열 수 있게 한다. 해결책을 먼저 확정하지 않는다. 이미 말한 생각은 `initialUserRef`로 연결하고, 추가 판단이 필요한 경우에만 `start`가 반환한 질문으로 이어간다.

새로 만드는 시스템에 기존 구현이 없다면 그 사실을 밝히고 제공된 요구와 자료로 시작한다. 조사를 위해 제품을 수정하거나 실제 사용자 데이터에 영향을 주는 실행을 하지 않는다. 관련 사실이 주제 판단에 필요하면 문서에 출처와 확인하지 못한 조건을 함께 정리하고 기존 `checkpoint` 시점에 저장한다. 조사는 사용자의 결정이나 측정 결과가 아니다.

진행 중 새 조건이 나오면 필요한 범위만 추가로 읽는다. 확인한 사실이 이전 판단을 바꾼다면 관련 단계를 검토하되 자동으로 사용자 결정을 바꾸지 않는다.

셸에서 파일을 검색할 때는 `rg --no-config --files` 또는 `rg --no-config -n '검색어' 경로`를 사용한다. `cat`과 `sed -n '1,30p' 경로`도 읽기 명령이다. 일반 `rg` 설정에는 외부 명령이 들어 있을 수 있어 훅이 차단할 수 있다. 호스트가 감싸진 도구 내부 호출도 검사하는지는 별도로 확인하며, 검증하지 않은 보호를 보장한다고 말하지 않는다.
