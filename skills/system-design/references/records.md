# 기록의 역할

## 프로젝트 설계와 ADR

설계 문서는 현재 요구사항과 처리 흐름을 설명한다. ADR은 선택한 내용과 이유를 설명한다. 사용자에게서 확정된 설계 선택은 작더라도 짧게 기록한다. 변수 이름 정리처럼 설계 판단이 없는 기계적인 수정은 ADR로 만들지 않는다.

ADR에는 다음 내용을 남긴다.

- 선택한 결정과 현재 상태
- 판단이 필요했던 배경
- 검토한 대안과 선택한 이유
- 얻는 점과 감수하는 점
- 사용자 선택 또는 근거 자료의 참조
- 검증 방법과 다시 검토할 조건

관련이 있는 결정에는 연결되는 사용자 결과, 규모와 수치의 측정 또는 가정 범위, 대안을 같은 조건에서 비교한 근거도 담는다. 확인하지 못한 비용이나 성능은 미확인으로 남기고 사용자 대신 목표를 확정하지 않는다.

AI의 제안은 제안 상태로 둔다. 사용자 선택이 명확해졌을 때만 확정한다. 사용자 대화 참조는 원문이 별도로 보존돼 있다는 뜻이 아니다. 원문을 열 수 없으면 확인할 수 있는 범위를 그대로 말한다.

결정을 바꾸면 이전 ADR을 보존하고 새 결정과 연결한다. 결정 확정, 구현 완료, 검증 완료는 별개다. 테스트에 통과했다는 이유만으로 운영 목표를 충족했다고 적지 않는다.

## 개인 Obsidian

개인 노트에는 현재 단계, 중요한 판단의 요약, 배운 내용, 남은 질문, 프로젝트 설계와 ADR 링크를 남긴다. 대화 원문이나 ADR 전문을 기본으로 복제하지 않는다.

학습 내용은 다음을 구분한다.

- AI가 설명한 내용
- 사용자가 이해했다고 말한 내용
- 사용자가 직접 설명한 내용

설명 제공만으로 이해 완료를 표시하지 않는다. 사용자의 감정이나 이해 정도를 추정해 넣지 않는다. 주제가 정리될 때 문서와 함께 한 번에 갱신하고, 사용자가 명시적으로 요청한 경우에도 갱신할 수 있다.

## 저장 오류와 직접 수정

CLI가 기록을 관리하도록 한다. 저장되지 않았는데 저장됐다고 말하거나, 충돌을 피하려고 새로운 ADR을 반복해서 만들지 않는다.

설계 또는 ADR 저장에 실패하면 단계를 완료하지 않는다. Obsidian만 갱신하지 못했다면 미반영 상태를 알리고 설계 대화는 계속할 수 있다. 이후 `sync`로 다시 반영한다.

직접 수정된 문서가 발견되면 원문을 보존한다. 무엇이 달라졌는지 읽고, 결정의 의미가 바뀌었으면 사용자에게 질문한다. 확인한 뒤 `reconcile`을 사용한다. 다른 도구나 셸로 충돌 검사를 우회해 덮어쓰지 않는다.

저장 도중 중단된 작업에서 사람이 파일을 수정했다면 `status`의 `pendingRecovery`에 확인할 파일이 나온다. 조회와 도움말은 계속 사용할 수 있다. 표시된 파일을 실제로 읽고 사용자와 확인한 뒤 `recover`로 현재 내용을 보존한다. 파일이 없어졌다면 그 사실도 확인한다. 영향을 받는 단계부터 인터뷰를 다시 진행하고, 중단된 결정을 완료로 바꾸지 않는다.

## 원문 보관

대화 원문은 기본적으로 호스트 세션에만 남는다. 임시 파일, 명령 입력 파일, 오류 로그, 프로젝트 파일에 원문을 추가로 저장하지 않는다. 명령에는 필요한 판단의 요약과 세션 참조만 전달한다.

개인 진행 정보에는 현재 질문, 단계별 사용자 발화 참조와 현재까지의 짧은 AI 해석을 남긴다. 이는 독립적인 전체 인터뷰 원문이 아니다. 원래 대화에 접근할 수 없으면 읽었다고 가정하지 않는다. 설계 문서와 진행 정보로 복원하고, 다음 판단에 필요한 내용만 확인한다.

초기 설정에서 사용자가 추가 보관을 명시적으로 켠 경우에만 훅의 원문 보관 기능을 사용한다. 승인 이후 해당 작업의 질문과 사용자 입력만 개인 위치에 보관한다. 관련 없는 대화나 과거 세션을 복사하지 않는다. AI가 사용자 원문을 별도 CLI 인자로 다시 보내지 않는다.
