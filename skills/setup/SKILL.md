# system-design 초기 설정

설계 기록을 어디에 둘지 정한다. 프로젝트의 설계와 ADR, 개인 Obsidian 기록, 진행 정보는 서로 다른 역할을 가진다.

설정만 호출할 때 Codex에서는 `$system-design:setup`, Claude Code에서는 `/system-design:setup`을 사용한다.

1. [진행 명령](../system-design/references/cli.md)을 읽고 `settings`로 기존 설정을 확인한다. 이미 정한 값을 다시 묻지 않는다. 변경 요청이 있으면 해당 값만 확인한다.
2. 개인 진행 정보의 기본 위치는 Git 밖의 `~/.local/state/system-design`이다. 이 위치를 사용할지 확인한다. 현재 단계, 남은 질문, 짧은 AI 해석, 문서 위치와 세션 참조를 기본으로 보관한다고 설명한다. 다른 위치를 선택하면 호스트를 시작할 때 `SYSTEM_DESIGN_STATE_DIR`을 지정하도록 안내하고, 기존 진행 정보를 자동 이동하지 않는다. 설치 캐시, 프로젝트나 Obsidian 볼트 안으로 옮기지 않는다.
3. Obsidian 볼트 후보를 확인하되 임의로 선택하지 않는다. 사용자가 사용할 볼트와 그 안의 기록 폴더를 정하게 한다. 프로젝트 자체가 볼트인 경우에도 ADR 원본과 개인 학습 기록의 위치를 구분한다.
4. 대화 원문 추가 보관 여부를 별도로 묻는다. 기본은 보관하지 않음이다. 추가 보관은 사용자가 명시적으로 선택한 경우에만 켠다. 이후 해당 작업의 대화만 개인 위치에 보관하며, 과거 세션을 일괄 복사하거나 Git에 넣지 않는다.
5. 선택한 내용과 훅에서 받은 현재 세션 `owner`로 `setup`을 실행한다. 추가 보관을 켤 때는 그 선택의 실제 `userRef`도 전달한다. 실패를 성공으로 표시하지 않는다. 설정 결과와 실제 경로를 짧게 보여준다.

프로젝트를 처음 등록할 때 기존 설계 문서와 ADR 위치를 확인한다. 후보가 여럿이면 사용자에게 묻는다. 기존 구조가 없으면 프로젝트의 `docs/system-design`과 `docs/adr`을 제안하고 선택받는다. 개인 Obsidian 노트의 위치도 확인한다. 사용자의 선택 없이 빈 문서나 폴더를 여러 곳에 만들지 않는다.

설정이 끝나면 초기 설정을 위한 입력 참조 수집도 끝난다. 설계를 자동 시작하지 않는다. 사용자가 지정한 작업을 `system-design`으로 명시 호출해 시작하거나 기존 작업을 이어간다. 설치 후 훅 검토가 필요하면 표준 호스트 화면을 안내한다. 신뢰 확인을 우회하는 명령을 실행하지 않는다.
