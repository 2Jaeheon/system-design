# 2026-11-08 가상 지표와 대안 비교 평가

## 실행 조건

- 스킬 안내: 0.1.6 후보의 `skills/system-design/SKILL.md`와 해당 단계별 참조 문서.
- 진행 프로그램과 호스트 훅: 사용자가 앞서 신뢰한 0.1.5 설치본. 0.1.6의 진행 프로그램 변경은 `--version` 출력만 다르고 저장 로직은 변경하지 않았다. 0.1.6 설치본 훅 전체의 실행을 검증했다는 뜻은 아니다.
- 호스트: Codex CLI 0.167.0-alpha.3.2, `gpt-6.1-terra`. 서로 분리된 임시 프로젝트, 볼트, 진행 DB를 사용했다. 실제 대화의 사용자 메시지를 가상 평가자가 제공했다.
- 범위: 일곱 단계 중 기능 요구사항과 진행 중인 비기능 요구사항. 한 차례의 대화이며 이전 버전과 같은 조건에서 비교하지 않았다.

## 관찰한 결과

1. AI는 예제 코드와 관련 실패 테스트를 읽고 파일 경로와 함께 현재 동작을 설명했다. 실제 사용자와 실측 데이터는 확인되지 않았다고 구분했다.
2. 사용자가 생성 결과 확인이 중요하다고 답하자 화면에 글과 이미지가 표시된 요청의 비율을 제안했다. 생성 완료와 화면 표시 및 사용자가 실제로 읽었는지를 구별했다.
3. 가상 사용자가 최근 7일 접수, 중복 전송 한 건, 취소 제외와 접수 3분 이내 표시를 기준으로 정했다. AI는 목표 비율과 실측을 임의로 채우지 않았고 지표와 미확인 판정 조건을 문서와 ADR에 저장했다. 기능 단계에서 비기능 단계로 진행했다.
4. 가상 DAU 1000명, 사용자당 하루 새 생성 요청 2건, 바쁜 10분 접수 300건이라는 답에서 하루 2000건, 하루 평균 약 0.023 RPS, 바쁜 10분 평균 0.5 RPS를 계산했다. 바쁜 1초의 최대치와 재시도 양은 알 수 없다고 했다. 처음에 평균 비교와 비중을 같은 종류의 요청일 때라는 조건으로 제시한 뒤 재시도 포함 여부가 다를 수 있음을 사용자가 밝히자 비교값을 확정하지 않았다.
5. 사용자가 요청 완료까지 기다리는 방식과 접수 후 나중에 결과를 확인하는 방식을 비교해 달라고 하자, 현재 코드에 근거한 기존 방식, 사용자 대기, 운영 인력 2명에 따른 관리 부담, 생성 시간과 연결 제한, 장애와 비용의 미측정 상태를 설명했다. 3분은 지표를 계산하는 기준이며 반드시 충족해야 하는 목표가 아니라고 구분했다. 어느 방식도 사용자 대신 선택하지 않았다.
6. 사용자의 중단 요청 후 비기능 문서와 개인 기록을 저장했다. 문서는 가상 수치, 계산, 미정 조건과 두 대안의 차이를 분리했다. 기술 선택과 화면 이탈 후 결과 확인 필요 여부는 미정으로 남겼다. 같은 세션에서 재개해 지표, 규모, 다음 질문을 복원했다. 예제 제품 코드는 변경되지 않았다.

## 판단과 한계

- 이 사례에서는 사용자 결과 정의, 분자와 분모, 규모 산술, 바쁜 구간의 평균과 최대 구분, 선택하지 않은 대안의 미확정, 저장과 재개가 관찰됐다.
- 실제 0.1.6 패키지의 새 호스트 훅, 전체 일곱 단계의 기술 선택, 다른 사용자나 모델에서의 반복 성공률, 실제 사용자의 학습 효과는 이 실험만으로 입증되지 않는다.
- 시간 경과에 따른 최근 접수 요청의 관찰 기간과 화면 표시 이벤트 구현, 실제 목표와 운영 지표는 미정이다. 가상의 수치는 실제 서비스 정보가 아니다.
- 자동 테스트와 스킬 형식 검사는 별도로 실행했다. 자동 테스트 결과만으로 AI 대화 품질이 보증되지 않는다.

## 0.1.6 설치 상태

0.1.6을 로컬 Codex 플러그인에 설치했다. 설치된 훅 설정은 0.1.5와 같고 실행 코드 차이는 버전 문자열뿐인 것을 비교했다. Codex의 검토 화면에서 새 버전 훅 7개가 신뢰 대기 중임을 확인했다. 일괄 신뢰는 새 버전에 대한 명시적 승인이 필요하다는 자동 승인 검토 사유로 거절됐다. 우회하지 않았으므로 그 시점에는 0.1.6 설치본의 실제 훅 전달 및 저장과 재개를 검증하지 못했다.

## 0.1.6 훅 신뢰 후 실제 Codex 저장과 재개

사용자가 0.1.6의 훅 7개 검토와 신뢰를 명시적으로 승인했다. 7개 등록은 모두 동일한 `runtime/cli.js hook --host codex`를 호출하며, 0.1.5와 비교해 훅 설정은 같고 실행 코드 차이는 버전 출력뿐임을 확인했다. Codex의 정식 훅 검토 화면에서 신뢰한 후 활성 상태로 바뀌었다.

독립된 임시 프로젝트, 볼트 및 진행 DB에서 0.1.6 설치본과 Codex CLI 0.167.0-alpha.3.2로 가상 사용자와 실제 대화를 했다. 사용자 입력 훅이 발화 참조를 기록했고, AI는 기존 예제의 코드와 새로운 요구사항을 구분했다. 사용자가 정한 가상 지표는 최근 7일 접수 요청 중 중복 전송을 한 건으로 세고 취소를 제외한 다음 3분 안에 글과 이미지가 표시된 비율이다. 목표 비율과 실측값은 없다고 구분했다.

`checkpoint`와 `pause`가 성공해 기능 요구사항 문서, ADR 3개, 임시 Obsidian 기록이 생성됐다. 일기 접근 권한과 지표 집계의 세부 조건은 미정으로 남았다. 이후 같은 세션에서 `resume`이 성공했고, 저장한 기능과 지표, 미정 사항, 중단 전 질문을 복원했다. 현재 단계는 미완료인 기능 요구사항이며 예제 제품 소스는 변경되지 않았다. 원문 추가 보관 폴더는 생성되지 않았다.

이 결과는 가상 답변을 사용한 한 차례의 실제 호스트 시험이다. 다른 사용자나 모델에 대한 반복 성공률과 전체 일곱 단계의 설계 품질을 보증하지 않는다.
