# 2026-11-08 가상 대화 평가

## 범위

- 검사 대상: system-design 0.1.4. 예제 프로젝트 `evaluation/fixture`와 임시 볼트 및 임시 진행 DB를 사용했다.
- 실행: Codex CLI 0.167.0-alpha.3.2, 모델 `gpt-6.1-terra`. 새 대화를 시작한 뒤 같은 세션에서 가상 답변을 세 번 보냈다.
- 비교 대상: 없음. 수정 전과의 우열이나 반복 실행 성공률은 판단할 수 없다.
- 가상 답변은 실제 사용자 요구사항이 아니다. 제품 코드와 실제 사용자의 진행 DB, 실제 Obsidian은 평가에 사용하지 않았다.

## 관찰한 결과

1. 첫 응답은 예제의 요청 처리, `PENDING` 저장, 외부 이미지 생성, `FAILED` 상태 저장과 성공 및 실패 결과를 설명했다. 외부 서비스와 실제 화면은 확인하지 않았다고 밝혔다. 관련 코드와 테스트를 읽었지만 사용자에게 보여준 첫 응답에는 파일 경로가 없었다.
2. 가상 사용자가 수동 재시도를 원한다고 하자, 실패 응답에 일기 ID가 없다는 코드상 사실을 짚고 어디에서 재시도할지 물었다.
3. 가상 사용자가 모른다고 하자 즉시 재시도와 목록에서 나중에 재시도하는 방법을 설명하고 추천안을 제시했다. 가상의 사용자가 선택하기 전에는 추천을 결정으로 기록하지 않았다.
4. 가상 사용자가 목록에서 재시도를 선택하고 저장을 요청하자, `checkpoint`는 `USER_EVIDENCE_REQUIRED`를 반환했다. 모델은 저장되지 않았고 공식 중단도 설정하지 못했다고 밝혔다. 임시 DB에는 사용자 발화 이벤트가 없었고, 설계 문서와 개인 기록도 생성되지 않았다.
5. 예제 제품 파일은 원본과 동일했다. 저장 실패는 이 실행에서 필요한 훅의 발화 참조를 받지 못해 발생했다. 이후 Codex CLI의 훅 검토 화면에는 새 버전의 훅 7개가 재검토 대기 중이라고 표시됐다. `PreToolUse` 상세에서 `system-design@system-design-local`의 0.1.5 실행 파일과 수정 후 재검토 필요 상태를 확인했다. 다른 호스트에서의 동작은 확인하지 못했다.

## 후속 수정과 한계

0.1.5의 지침에는 주요 현재 동작을 설명할 때 실제 파일 경로를 보여주는 요구와, 훅의 세션 정보나 사용자 발화 참조가 없을 때 공식 작업을 시작하지 않고 미저장 상태를 먼저 알리는 요구를 추가했다. 이는 모델에게 주는 지침이며, 실제 환경에서 항상 지켜진다는 보장은 없다. 당시에는 훅 연결 문제 자체가 해결됐다는 뜻은 아니었다.

0.1.5를 별도 임시 프로젝트에서 한 번 더 실행했다. 모델은 훅 정보가 없어 기록할 수 없다고 먼저 알렸고, 관련 코드와 테스트를 읽어 파일 링크와 함께 설명했다. 임시 진행 DB에 공식 작업을 만들지 않았다. 훅 전체 신뢰 시도는 자동 승인 검토에서 거절됐으므로 신뢰 절차를 우회하지 않았고, 그 시점에는 실제 Codex의 훅 연결 후 저장과 재개를 검증하지 못했다.

소스의 `tests/cli-conversation.test.ts`는 별도의 합성 이벤트로 CLI 저장, 재개, 문서 충돌을 검사한다. 이는 실제 Codex 대화에서 훅이 자동으로 발화를 전달한다는 증거가 아니다. 실제 사람이 학습하기 편했는지에 대한 평가도 아직 없다.


## 훅 신뢰 후 실제 Codex 저장과 재개

사용자가 0.1.5의 훅 7개 검토와 신뢰를 명시적으로 승인했다. 일곱 등록이 같은 `runtime/cli.js hook --host codex`를 실행하는 것을 파일에서 확인하고, Codex 훅 검토 화면의 정식 신뢰 기능을 사용했다. 신뢰 검사를 우회하는 옵션은 사용하지 않았다.

별도 임시 프로젝트, 임시 볼트, 임시 진행 DB에서 Codex CLI 0.167.0-alpha.3.2와 gpt-6.1-terra로 가상 대화를 진행했다. 첫 질문 전에 예제 요청 처리 경로와 실패 테스트를 파일 링크와 함께 설명했고, 실제 `UserPromptSubmit` 훅이 이 테스트 대화의 사용자 발화 참조를 저장했다.

가상 사용자는 실패한 일기를 목록에서 확인해 기존 일기로 재시도한다고 답했다. `checkpoint`가 성공해 설계 문서, ADR, 임시 Obsidian 노트가 생성됐고 진행 버전이 0에서 1로 바뀌었다. ADR은 가상 사용자 선택의 참조를 보관하고 구현과 검증을 대기로 표시했다. 기능 요구사항은 완료되지 않았다. `pause`가 성공한 뒤 같은 Codex 세션에서 재개 요청을 보냈고 `resume` 성공 후 저장된 선택, 미정 사항, 중단 전의 다음 질문이 복원됐다. 제품 예제의 소스는 변경되지 않았다.

이는 가상 사용자 답변을 이용한 한 차례의 실제 Codex 호스트 시험이다. 다른 모델과 호스트, 모든 대화, 모든 도구 경로의 보호나 실제 사용자의 학습 효과를 증명하지 않는다.
