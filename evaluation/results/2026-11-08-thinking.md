# 생각을 돕는 대화와 단계 이동 평가

## 대상과 방법

- 0.1.7 후보의 스킬 안내와 신뢰가 이미 승인된 설치 버전 0.1.6의 실행 코드를 함께 사용했다. 0.1.7 설치본과 그 훅을 검증한 시험은 아니다.
- 임시 프로젝트에서 실제 Codex 대화를 진행하고, 사람이 가상 사용자의 답변을 입력했다. 실제 사용자 학습 효과를 측정한 결과는 아니다.
- 일기 생성 기능에서 사용 대상과 범위, 실패 상황을 정하고 기능 요구사항에서 비기능 요구사항으로 이동했다. 실험에 사용한 대화 로그와 기록은 이 저장소에 포함되어 있지 않다.

## 관찰

- 사용자가 선택하기 어렵다고 하자 AI가 조회 범위 선택지와 결과를 설명하고 사용자에게 판단을 요청했다.
- 실패한 글을 다시 사용할지 미정인 상황을 현재 단계의 범위 판단으로 취급해 이동을 멈추고 필요한 질문을 했다.
- 제외하기로 정한 뒤 요구사항 문서와 결정 기록을 저장하고, 기능 요구사항 완료 근거와 아직 정하지 않은 보관 조건을 설명한 후 비기능 요구사항으로 이동했다.
- 다음 단계의 첫 질문은 규모, 속도, 장애, 보존을 함께 물어 답하기에 넓었다. 이를 발견한 후 여러 판단을 한 질문에 묶지 말라는 지침을 추가했다. 추가된 최종 문구로 같은 대화를 다시 실행하지는 않았다.
- 프로그램은 저장과 단계별 필수 항목 등을 확인하지만, 판단 근거가 실제로 타당한지 또는 사용자가 이해했는지 보장하지 않는다.

## 자동 검증

- TypeScript 빌드와 기존 자동 테스트 82개를 통과했다.
- 스킬 형식 검증을 통과했다.
- 단일 가상 시나리오와 자동 테스트만으로 다양한 실제 대화의 품질을 보장할 수 없다.

## 설치된 0.1.7 재시험

- 일시: 2026-11-08, 한국 시간.
- 설치된 0.1.7과 원본 배포 패키지가 동일함을 확인했다. 7개 훅을 검토하고 Codex의 훅 화면에서 신뢰했다.
- 임시 프로젝트와 별도 상태 DB, 임시 볼트를 이용해 실제 Codex 대화를 실행했다. 사용자의 답변은 평가를 위한 가상 답변이며 실제 서비스 이용자의 학습 효과를 나타내지 않는다. 원문 추가 보관은 끈 상태였다.
- 사용자가 조회 대상을 모르겠다고 하자 AI는 선택지와 결과를 설명하고 사용자의 선택을 기다렸다.
- 선택한 조회 범위와 미정인 실패 후 재생성 여부가 설계 문서, 결정 기록과 개인 노트에 저장되었고, 일시 중단 후 실제 대화 재개에서 미정 질문을 복원해 선택지 차이를 설명했다.
- 사용자가 기능 범위를 확정하자, 저장 후 기능 요구사항에서 비기능 요구사항으로 이동하며 이유와 다음에 정할 내용을 설명했다. DB 상태도 2단계와 남은 보관 조건을 표시했다.
- 남은 문제: 다음 단계의 첫 질문이 속도, 규모, 장애, 데이터 보존을 한꺼번에 열거하고 끝에 하나만 말해 달라고 덧붙였다. `src/engine.ts`에 기본 질문이 여러 주제로 고정되어 있어 스킬 안내를 보강해도 첫 질문이 충분히 좁혀지지 않았다. 개선하려면 기본 질문 생성 방식과 저장된 대기 질문의 호환성을 함께 검토해야 한다. 이번 시험에서는 코드를 수정하지 않았다.
- 한 가지 가상 시나리오에서 관찰한 결과이며 AI의 판단 품질이나 실제 사용자의 학습 성과를 보장하지 않는다.
