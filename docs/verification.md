# 0.1.0 검증 결과

검증일: 2026-11-04

## 자동 검사

Node 26.5.0에서 TypeScript 빌드와 자동 검사 74개가 모두 통과했다. Codex와 Claude Code 패키지는 같은 공통 스킬과 진행 관리 코드를 사용한다.

검사는 다음 동작을 포함한다.

- 사용자의 첫 생각과 단계별 검토 근거가 없으면 다음 단계로 이동하지 않는다.
- 설계 완료만으로 구현을 시작하지 않는다. 구현 시작에는 별도의 사용자 발화가 필요하다.
- 설명 제공과 사용자의 이해 표현을 구분한다.
- 오래된 문서 버전과 이전 소유 세션의 변경을 거부한다.
- 여러 원본 문서를 저장하다 실패하면 앞서 쓴 문서도 복구한다.
- 사람이 수정하거나 삭제한 문서를 덮어쓰지 않는다. 저장 중단과 수동 수정이 겹쳐도 현재 파일을 확인하고 복구할 수 있다.
- Obsidian 갱신 실패를 별도로 표시하고 중복 없이 재시도한다.
- 대화 원문은 기본으로 추가 저장하지 않는다.
- ADR에 설계 문서의 버전, 인터뷰 참조, 코드 링크와 실제 검증 결과를 연결한다.
- AI 요약과 제목의 오기를 정정해도 기존 답변의 참조와 결정 본문을 보존한다.
- 두 호스트 패키지에 스킬과 훅을 중복 등록하지 않는다.

## Codex CLI 실제 실행

Codex CLI 0.166.0-alpha.5.1에서 임시 프로젝트와 임시 볼트를 사용했다. 개인 Obsidian과 실제 작업의 진행 정보에는 테스트 자료를 넣지 않았다.

확인한 동작은 다음과 같다.

1. 플러그인 설치와 스킬 두 개, 초기 설정 스킬, 훅 일곱 개의 인식을 확인했다. 훅은 표준 검토 화면을 거쳐 신뢰했다.
2. 명시 호출 후 선택한 위치와 원문 미보관 설정을 저장했다. 요구사항의 답을 대신 만들지 않고 사용자 생각을 기다렸다.
3. 모르는 개념을 쉽게 설명하고 요구사항 질문으로 돌아왔다. 학습 기록에는 설명 제공만 남았고, 사용자 이해로 표시되지 않았다.
4. 설계 중 `apply_patch` 호출이 실제 훅에서 거부됐다. 대상 파일의 내용도 그대로였다.
5. 프로세스를 종료하고 다시 열어 같은 작업의 단계와 질문을 이어갔다.
6. 사용자 선택에 따라 요구사항 문서와 ADR, Obsidian 진행 기록을 저장했다. 품질 목표가 미정인 상태에서 다음 단계로 이동하지 않았다.
7. 실제 대화에서 발생한 잘못된 AI 요약과 ADR 제목을 정정했다. 이전 내용과 수정 이유를 보존했고, 결정 본문과 기다리는 질문은 유지했다.
8. 별도의 일반 대화에서 파일을 정상적으로 읽었다. 해당 대화는 플러그인 작업으로 연결되지 않았고 사용자 입력 참조도 수집되지 않았다.
9. 저장된 문서의 해시와 진행 정보가 일치하고, 설치된 파일 26개가 배포 패키지와 같은 것을 확인했다.

여섯 단계 전체의 이동, 구현 요청 대기와 검증 완료 조건은 자동 검사로 확인했다. 실제 Codex 대화에서 여섯 단계 전체의 설계 품질을 평가한 것은 아니다.

## Claude Code

패키지 구성과 공통 기능, Claude 훅 입력과 출력의 자동 검사는 통과했다. Claude Code 프로그램 안에서 실제 대화를 실행한 검증은 아직 하지 않았다.

## 확인 범위

훅은 호스트가 제공하는 실행 경로에서 동작한다. 모든 파일 변경을 막는 파일시스템 보안 장치는 아니다.

사용자 발화 참조는 해당 발화가 존재함을 확인한다. AI 해석이 정확한지까지 보증하지 않는다. 뜻이 모호하면 다시 질문하고, 잘못 요약한 내용은 원래 참조와 정정 이력을 남겨 고친다.

개인 설정은 첫 사용에서 선택한다. 테스트용 설정을 개인 기본값으로 설치하지 않았다.
