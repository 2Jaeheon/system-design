# system-design

Codex에 추가해 사용하는 플러그인입니다. AI와 대화하면서 시스템 설계를 단계별로 진행하고, 결정한 내용과 이유를 문서로 남깁니다.

Claude Code에서 사용할 수 있는 패키지도 만들 수 있습니다.

## 어떻게 진행하나요?

설계할 기능을 말하면 AI가 필요한 질문을 합니다. 사용자가 생각을 말하면 AI는 빠진 조건을 확인하고, 필요할 때 다른 방법과 그 차이를 설명합니다. 한 주제가 정리되면 결정한 내용과 아직 남은 질문을 저장합니다.

```mermaid
flowchart LR
    A["설계할 기능을 말해요"] --> B["생각과 조건을 정리해요"]
    B --> C["필요한 방법을 비교해요"]
    C --> D["결정과 남은 질문을 저장해요"]
    D --> B
```

기존 프로젝트를 설계한다면 관련 코드와 테스트를 먼저 살펴봅니다. 확인한 현재 동작과 앞으로 정해야 할 내용을 구분해 설명합니다.

새로운 설계는 다음 일곱 단계를 순서대로 진행합니다.

1. 기능 요구사항: 만들 기능과 이번에 다루지 않을 범위를 정합니다.
2. 비기능 요구사항: 사용 규모, 속도, 장애 대응처럼 기능이 동작할 조건을 정합니다.
3. 핵심 객체: 기능에서 필요한 정보와 그 관계를 정합니다.
4. API: 시스템이 주고받을 요청과 응답을 정합니다.
5. 전체 설계: 각 구성 요소의 역할과 연결을 정합니다.
6. 상세 검토: 중요한 처리 방식과 실패 상황을 자세히 살펴봅니다.
7. 설계 평가: 처음 정한 요구사항을 설계가 충족하는지 확인합니다.

각 단계에서 중요한 질문을 하나씩 살펴봅니다. 설계가 끝난 뒤에는 사용자가 구현을 요청하면 기능 코드 작업을 시작합니다.

## 시작하기

### 1. 준비하기

- Codex CLI가 필요합니다.
- Node.js 26.5.0 이상, 27 미만이 필요합니다. 패키지를 만들 때와 플러그인을 실행할 때 사용합니다.
- 기록을 남길 기존 Obsidian 볼트가 필요합니다. 볼트는 Obsidian에서 사용하는 노트 폴더입니다.

이 저장소를 내려받은 뒤, 터미널에서 저장소 폴더로 이동해 다음 명령을 실행합니다.

```sh
npm ci
npm run package
```

첫 번째 명령은 필요한 개발 도구를 설치합니다. 두 번째 명령은 `dist` 폴더에 Codex와 Claude Code용 패키지를 만듭니다.

### 2. Codex에 설치하기

같은 폴더에서 다음 명령을 실행합니다.

```sh
codex plugin marketplace add ./dist
codex plugin add system-design@system-design-local
```

설치 상태는 다음 명령으로 확인할 수 있습니다.

```sh
codex plugin list --marketplace system-design-local --json
```

설치 후에는 훅을 검토하고 신뢰해야 합니다. 훅은 Codex의 대화와 도구 사용 중에 플러그인이 실행하는 기능입니다. Codex CLI 대화에서 `/hooks`를 입력하거나 앱의 훅 검토 화면을 이용합니다. 훅이 연결되지 않으면 설계 작업을 공식적으로 시작하거나 저장할 수 없습니다.

### 3. 기록 위치 설정하기

설계할 프로젝트를 열고 새 Codex 대화에서 다음을 입력합니다.

```text
$system-design:setup 초기 설정을 진행해줘.
```

안내에 따라 개인 진행 정보와 Obsidian 노트의 위치를 선택합니다. 대화 원문을 추가로 보관할지도 여기에서 정합니다. 기본 설정은 추가로 보관하지 않는 것입니다.

프로젝트에서 처음 설계를 시작할 때는 설계 문서와 결정 기록을 어디에 둘지도 선택합니다. 기존 위치가 없다면 `docs/system-design`과 `docs/adr`을 제안합니다.

### 4. 설계 시작하기

설계할 내용을 적어 다음처럼 입력합니다.

```text
$system-design:system-design 일기 이미지 생성이 실패했을 때 다시 시도하는 기능을 함께 설계해줘.
```

이미 일기 기능이 있는 프로젝트라면 AI가 기존 실패 처리 코드를 읽고, 사용자가 어디에서 다시 시도할지 질문할 수 있습니다. 사용자가 고른 방법과 이유는 주제가 정리될 때 기록합니다.

AI의 질문에 생각을 답하면 됩니다. 모르는 내용은 쉽게 설명해 달라고 요청할 수 있습니다. 잠시 멈추고 싶다면 `지금까지 정한 내용과 남은 질문을 저장하고 멈춰줘`라고 말합니다.

저장 성공을 확인한 뒤 같은 세션에서 다음처럼 이어갈 수 있습니다.

```text
$system-design:system-design 일기 이미지 재시도 설계를 이어서 진행해줘.
```

다른 세션이나 도구에서 이어갈 때는 먼저 작업 인계가 필요합니다.

## 기록은 어디에 남나요?

- 프로젝트 설계 문서: 요구사항과 현재 설계 내용을 기록합니다.
- 프로젝트 결정 기록: 선택한 방법, 그 이유와 감수할 점을 기록합니다. 이 문서를 ADR(Architecture Decision Record, 설계 결정 기록)이라고 합니다.
- Obsidian 노트: 현재 단계, 중요한 판단, 배운 내용과 남은 질문을 정리합니다.
- 개인 진행 정보: 작업의 단계와 저장된 질문을 관리합니다. 기본 위치는 `~/.local/state/system-design`입니다.

대화 원문은 기본적으로 플러그인이 추가 보관하지 않습니다. 초기 설정에서 추가 보관을 직접 켜면 해당 작업의 이후 사용자 입력과 저장된 질문 정보를 개인 위치에 보관합니다.

대화의 모든 답변을 바로 저장하지는 않습니다. 한 주제가 정리되거나 사용자가 저장을 요청할 때 기록합니다. 갑자기 대화가 끊기면 마지막 저장 이후의 내용은 기록에 없을 수 있습니다.

## Claude Code에서 사용하기

패키지를 만든 후 다음 명령으로 Claude Code에서 패키지를 확인하고 실행할 수 있습니다.

```sh
claude plugin validate ./dist/claude --strict
claude --plugin-dir ./dist/claude
```

Claude Code에서는 `/system-design:setup`으로 설정하고 `/system-design:system-design`으로 설계를 시작합니다. Claude Code에서의 실제 대화 검증은 아직 하지 않았습니다.

## 검사와 참고 자료

다음 명령은 코드를 빌드하고 자동 테스트를 실행합니다.

```sh
npm test
```

자동 테스트와 실제 AI 대화 검증은 다릅니다. 테스트 통과만으로 모든 대화에서 설계가 올바르게 진행된다고 보장할 수 없습니다. 또한 훅은 설계 중 코드 수정을 막는 보조 기능이며, 모든 파일 변경을 막는 보안 장치는 아닙니다.
